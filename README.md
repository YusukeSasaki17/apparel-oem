# 生産営業システム — Claude Codeで作った担当者専用の業務OS

アパレルOEM担当営業が、Claude Codeを使って**自分の業務をまるごとシステム化**したリポジトリです。

---

## コンセプト

> 「AIに仕事を頼む」じゃなく、「AIと一緒に組織を作る」

担当者（自分）がインプットを入れると、5人のAI責任者が動いてアウトプットを返す構造です。

```
担当者の日記・考え事・案件データ
        ↓
  ┌─────────────────────┐
  │  5人のAI責任者が処理  │
  │  営業 / プロダクト   │
  │  マーケ / 財務 / 技術 │
  └─────────────────────┘
        ↓
  毎朝のブリーフィング・粗利アラート・納期警告・顧客分析...
```

---

## フォルダ構造

```
apparel-oem-system/
│
├── インプット/              ← 担当者の一次情報（最優先で参照）
│   ├── 日記/               ← 日々の気づき・判断・懸念
│   ├── 考え事/             ← 戦略的思考メモ
│   └── 一次情報/           ← 顧客リスト・最新方針
│
├── 営業責任者/              ← 顧客開拓・商談・クロージング
│   ├── 顧客/               ← 顧客ファイル（データの正本）
│   ├── 対話ログ/           ← 商談・メール記録
│   ├── 見積もり/           ← 見積CSVと出力HTML
│   └── レポート/           ← 朝礼・週次・顧客分析・納期管理
│
├── プロダクト責任者/         ← 商品企画・サンプル・品質
│   ├── 企画カード/         ← 横展開用の商品アイデア
│   └── ロードマップ/       ← 品番×工場×アイテム分析
│
├── マーケティング責任者/     ← 認知・集客・ブランディング
├── 財務責任者/              ← 請求・契約・入金・粗利管理
├── 技術責任者/              ← AI活用・業務自動化
│
├── CLAUDE.md               ← Claude Code向けルール正本
├── AGENTS.md               ← Codex（監査役AI）向け定義
└── .claude/
    ├── agents/             ← 5責任者の人格・判断基準定義
    └── skills/             ← スラッシュコマンド群
```

---

## スラッシュコマンド（毎日使う道具）

| コマンド | 何をするか |
|---|---|
| `/morning-briefing` | 予算・粗利・納期・入金を1画面に統合。毎朝これで全体把握 |
| `/日記` | 担当者の気づきを記録。全AI責任者への引き継ぎ入口 |
| `/cost` | FOB金額を入れると粗利を即答・アラート判定 |
| `/粗利チェック` | 全案件の粗利5%未満🚨/10%未満⚠を一覧化 |
| `/納期管理` | 全案件SHIPDATEを確認し危険度判定 |
| `/入金確認` | 請求管理CSVから未入金・期日超過を検出 |
| `/顧客分析 [顧客名]` | 指定顧客の深掘り分析とアクション提案 |
| `/週次レポート` | 直近7日間の変化・差分に特化したレポート |
| `/最新方針` | 日記・考え事から全責任者への共通ブリーフィングを生成 |

## 設計のこだわり

**SSOT（Single Source of Truth）**
データの正本は1箇所だけ。レポートは全部スキルが自動生成するので、手で書き換えない。

**Codexが監査役として並走**
Claude CodeとCodexを役割分担。日々の構築はClaude Code、数字・期限・ルールの監査はCodex。

**インプット→処理→アウトプットの一方向**
担当者が日記・案件データを入れると、AIが判断して出力を返す。AIに聞くより先にインプットを整備する習慣が鍵。

## 使い始めた動機

担当営業として日々細かい変化の多い、顧客・案件・粗利・納期を全部頭の中で管理していた限界を感じ、  
「どうせAI使うなら、仕組みごと設計してしまおう」と作り始めました。
